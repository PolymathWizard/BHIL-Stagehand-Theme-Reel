# ADR-003 · Public guardrails and collision notes

**Status:** Accepted · 2026-11-10

## Context

Each internal card carries two fields that depend on knowing the source work:

- **Homage guardrails**, a theme-specific list of things never to use. Several entries used the work's own invented terms to name the banned element.
- **Ledger proximity**, which named BHIL's shipped properties that a theme sits near, so the U3 check could avoid repeating a look.

Both are valuable in public: guardrails stop accidental copying, and collision notes teach the ledger habit. But printed as written, they would publish the very names and terms the public edition removes.

## Decision

1. **Guardrails are rewritten at the level of the banned element, not the work.** Each one names a category of thing (a vehicle type, a costume silhouette, a title-sequence composition) in plain description, without the work's own vocabulary. Specificity is kept where it protects: the vector theme still forbids light-racing vehicles and throwing-disc weapons; the corporate theme still forbids the series' vocabulary for departments and workers.
2. **Ledger proximity becomes a collision note.** Instead of naming BHIL properties, each note names the *kind* of build the theme sits near (sci-fi dashboards, contour-terrain boards, watercolor poetry builds) and what to change to stay clear. The field is renamed "Collision note" in canon, cards and figures.
3. The internal brief keeps the original fields. The public edition does not try to mirror them.
4. References to BHIL's internal framework sections (section numbers, recipe numbers) are replaced with plain descriptions, and the stage letters are explained by what each stage does ([how agents use the codex](../codex/how-agents-use.md#stage-letters)).

## Consequences

- An outside agent can apply every guardrail without knowing the source work, which is the point: the guardrail protects the output, not the reader's trivia.
- The validator's deny list checks the rewrites like any other text.
- Collision notes are less precise than a named ledger. Teams should keep their own ledger of shipped builds and read the note against it.

## Alternatives considered

- **Drop the guardrails from the public edition.** Rejected: the guardrails are the most practical protection against a look sliding into a copy.
- **Keep the original wording behind a "spoilers" fold.** Rejected: folded text is still published text.

## Settling criteria

If a guardrail proves too vague to act on (an auditor cannot decide PASS or FAIL from it), sharpen the description of the element, never by naming the work.
